# Seasons, and how to check the ladder did not pick your world

The seed pool is built in advance. That is what makes a 1v1 race a test
of play rather than a lottery over spawns - and it means whoever runs
this ladder knows every world in the pool before any of them is dealt.
The operator also plays here. "We would not deal ourselves a world we
had studied" is exactly the sort of assurance this project exists to
stop asking players to accept.

So the draw is not a choice. It is a calculation anyone can repeat.

## The scheme

A season opens with a random 32-byte secret. Its SHA256 is published in
the table below **before the season's first match**, in a commit that is
timestamped by GitHub and cannot be revised without a visible history
rewrite.

Every draw then takes its randomness from `HMAC(secret, matchId)`. Given
the candidates and the match id, which seed is dealt is fixed. The server
has no say in it.

Each match also records a commitment to what it dealt:

    SHA256("alt-draw-v1" | seasonId | matchId | nonce | seedPairId | overworldSeed | netherSeed)

It is published the moment the match exists, on `GET /matches/{id}/detail`,
so both players can write it down at the start. The nonce that opens it
is withheld until the match is over and published with it - a commitment
handed out with its own nonce commits to nothing, and a live one would
hand out the world.

At season close the **secret itself** is published in the table below.
From that point anyone can run

    npx tsx backend/scripts/verifyDraws.ts <matches-table> --season <file>

and replay every draw of the season: re-derive the order over the
candidate list recorded on each match, and check the seed the server
dealt is the one the arithmetic demands. Any match where it does not is
named.

## What this proves

That the operator could not hand-pick a world for a match, and could not
change one afterwards. Both would require producing a secret whose hash
was already published, before the matches were played.

## What it does not prove

Written here rather than left to be discovered, because a proof that
overstates itself is worse than none.

- **The candidate list is taken on trust.** The draw runs over the pool
  rows the server offered it. A list with rows quietly left out of it
  verifies perfectly. Closing this needs the pool published, which burns
  the pool - the same trade that keeps it secret in the first place.
- **The match id is generated by the server**, immediately before the
  draw. An operator willing to throw away match ids can re-roll one
  until the derived seed suits them, and it leaves no trace. The fix is
  a draw key mixing in a nonce from each client, fixed on the queue row
  before the pairing exists; it needs a mod change and is logged in
  TODO.md.
- **Verification is retrospective.** Until the secret is published,
  nobody outside can check a single draw. That is what the season
  boundary is for.
- **None of this touches memorisation.** A player who recognises a world
  at spawn is a pool rotation problem, not a draw problem.

A match drawn while no season secret was configured is stamped
`unverifiable` on its own record and reported as unaudited, never as
passing.

## Seasons

| season | opened | SHA256(secret) | state |
|---|---|---|---|
| _none open yet_ | | | |

Open one with `npx tsx backend/scripts/newSeason.ts <season-id>`, paste
the row it prints, **push it**, and only then deploy. Deploying first
would mean matches drawn from a secret nobody had committed to, which
proves nothing: the operator could roll a different secret afterwards
and publish whichever one made the season look right. The order is the
mechanism.

At close, add the secret to that season's row and set its state to
`closed`.
